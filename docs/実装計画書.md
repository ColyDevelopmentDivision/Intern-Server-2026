# 実装計画書

## メイン課題1: 重み付き抽選

### 目的

`POST /api/gacha/draw` が毎回同じアイテムを返さず、`gacha_detail_master.weight` に応じて抽選するようにする。

### 実装内容

`GachaService.DrawOneAsync` を実装

1. ガチャの排出プールを取得する。
2. 空プール、負の weight、合計 weight が0以下の場合は例外にする。
3. `0以上、合計weight未満` の乱数を生成する。
4. weight の累積値と乱数を比較し、当選した `item_id` を返す。

乱数には `Random.Shared.NextInt64`、合計値には `long` を使用した。10連は既存の `DrawManyAsync` がこの処理を10回呼び出すため、そのまま重み付き抽選になる。

### 確認結果

- Docker の MySQL は `healthy`、phpMyAdmin は `Up`。
- Swagger と phpMyAdmin は HTTP 200 で表示できた。
- `POST /api/gacha/draw` の10連で、複数の `item_id` が出現した。
- デバッグ用単発抽選を1000回実行し、全8種類が出現した。
- 実測値は設定値に近い結果になった。

| item_id | weight | 実測 |
|---|---:|---:|
| 2001 | 1% | 0.8% |
| 2002 | 1% | 0.4% |
| 2003 | 8% | 9.6% |
| 2004 | 10% | 10.3% |
| 2005 | 30% | 32.2% |
| 2006 | 25% | 22.4% |
| 2007 | 15% | 15.5% |
| 2008 | 10% | 8.8% |

### 気づき

最初の確認では Docker Desktop が起動しておらず、MySQL 接続エラーで API が `500` になった。API のエラーは、まずログと依存サービスの状態を確認する。
重さを編集して反映される仕組みがあることは知っていたが、実際に見て触ったことがなかったため面白かった。
