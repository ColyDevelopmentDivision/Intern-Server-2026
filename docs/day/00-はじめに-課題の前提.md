# 00. はじめに — 課題の前提

サーバー会に取り組む前に、この章を読んでください。

---

## 1. AI ツールを使ってOK

普段使っている AI ツール (ChatGPT / GitHub Copilot / Cursor / Claude Code など) があれば、自由に使ってください。

課題は全部ローカルで完結します (Docker + localhost API)。機密情報は登場しないので、AI にコードを投げるセキュリティ懸念は気にしなくて大丈夫です。

### 【必須】VSCode に GitHub Copilot を繋いでいる人は、インライン提案を切ってください

VSCode で GitHub Copilot にサインインしていると、AI に質問しなくても、入力中のコードの続きが薄い文字 (インライン提案) で表示され、Tab キーで確定されます。課題では **コードの続きは自分で考えて書いてほしい** ので、課題を始める前に必ず切ってください。

**手順** (どちらか一方でOK。結果は同じです):

- 画面右下のステータスバーにある Copilot アイコンをクリックし、メニューでインライン提案のチェックを外す
- 設定画面 (`Ctrl+,` / Mac は `Cmd+,`) で `github.copilot.enable` を検索し、`*` の値を `false` にする

AI に質問すること自体は引き続きOKです。Copilot Chat や ChatGPT などに「何を聞くか」を自分で組み立てて使ってください。

## 2. 実装計画書について

**各課題に着手するタイミング** で、その課題で **何を作るか** を書き出す道具として **実装計画書** を用意しています（最初に全課題ぶんまとめて書く必要はありません）。

書く内容の例:
- 実現する機能を自分の言葉で言い直す（例: 「サーバーにユーザーのアイテム所持数を保存・更新する」）
- **なぜその機能が必要なのか**（例: 「所持数をサーバーに保存しないと、次にアプリを開いた時にアイテムが消えてしまうから」）
- **サーバーがどういう手順で処理するのか**（例: 「リクエストを受け取る → DB から所持データを取得 → プログラム側で加算 → DB に書き戻す」のように分解して並べる）
- そのコードを作るために、AI に何を聞くか / 何を調べるか
- **書き方の候補が複数あった時、どれをどんな理由で選んだか**（例: 「エラーメッセージを英語で書くか日本語で書くか迷い、Swagger で自分が読んで分かりやすい日本語にした」）

フォーマットは自由です。テンプレ ([`実装計画書-テンプレート.md`](./実装計画書-テンプレート.md)) もあるので、良ければコピーして使ってください。

---

## 3. 提出について

提出物は次の 2 つです。

- **実装計画書**: 全員提出。リポジトリ内の `docs/` フォルダなどに `実装計画書.md` として置いてください
  - コードまで書けた課題は、「AI に何を聞いたか」など 1〜2 行のメモで OK
  - コードを書くところまで手が回らなかった課題は、「サーバーがどういう手順で処理するのか」を少し詳しめに書いてください（書きかけ・AI 相談メモでも OK）
- **実装したコード**: 書けたところまで提出

### 手順

1. 当日の最初に、スタッフから指定された名前で **自分のブランチを作成** してください。以降の作業はすべてそのブランチ上で行います
2. 提出するときは、実装計画書とコードをそのブランチにコミット → push してください

上記の操作は **SourceTree** で行ってください (使い方は別マニュアル参照)。
