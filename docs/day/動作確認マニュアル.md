# 動作確認マニュアル

実装した API の動作確認方法をまとめたマニュアルです。

---

## 環境確認 (課題に取り組む前に)

1. Docker Desktop が緑色 (Running) であること
2. スタッフから指定された名前で作成した自分のブランチを checkout していることを確認
3. VSCode で **Open Folder** から `Intern-Server-2026` のフォルダを開く
4. ターミナルで `docker compose up -d` を実行、`docker compose ps` で `mysql` が `healthy`、`phpmyadmin` が `Up` (running) になること (healthcheck を定義しているのは mysql のみ)

![`docker compose up -d` 実行完了 (MySQL healthy, phpMyAdmin started)](./images/Terminal-docker-compose-up完了.png)

5. サーバー起動: 下のどちらかの方法で起動する
    - **方式A（VSCode）**:
      1. 左サイドバーの「実行とデバッグ」ビュー（`Cmd+Shift+D` / `Ctrl+Shift+D`）を開く
      2. 上部ドロップダウンで **「.NET Core Launch (InternApi / http)」** を選択
      3. 緑▶ボタンをクリック
    - **方式B（ターミナル）**:
      1. `cd src/InternApi`
      2. `dotnet run --launch-profile http`

![`dotnet run --launch-profile http` の起動ログ (cd src/InternApi 後の実行例)](./images/Terminal-dotnet-run-launch-profile起動.png)

6. ブラウザで <http://localhost:5109/swagger> が開けばOK

## 動作確認の仕方

### Unity から叩く

クライアント会で使用した Unity プロジェクトから、ローカルで起動したサーバーに繋がって動作します。

方法はスタッフに確認してください。

### Swagger から叩く

<http://localhost:5109/swagger> から実装した API を直接叩けます。

具体的な操作方法は下の [Swagger の使い方](#swagger-の使い方) 節、叩ける API の一覧は [エンドポイント一覧](#エンドポイント一覧) 節を参照してください。

### phpMyAdmin (DB 直接確認) の役割

Unity や Swagger を叩いた後の **データ変化を DB レベルで確認する** 手段。<http://localhost:8080> から `intern_user.user_items` を見ると、Grant / Consume が正しく効いているかがわかります。マスタいじりワーク (`./challenges/2-master-workshop.md`) の中心ツールでもあります。

## Swagger の使い方

1. <http://localhost:5109/swagger> にアクセス
2. 対象のエンドポイント (例: `POST /api/gacha/draw`) をクリック
3. **[Try it out]** ボタン → 必要なパラメータを入れて **[Execute]**

![Swagger の `POST /api/gacha/draw` エンドポイント (Body に `{"gachaId": 1}` を入れて Execute)](./images/Swagger-gacha-draw-エンドポイント.png)

4. 下に「Response body」で結果が確認できます

![初期状態の Response body (10 件すべて `itemId: 2001`)](./images/Swagger-gacha-draw-response-2001並び.png)

コードを書き換えたら、`dotnet run` を **停止して再起動** すると反映されます。
(`Ctrl + C` で止めて、再度 `dotnet run` コマンド または VSCode の実行を再起動。)

## エンドポイント一覧

Swagger UI に表示される API の一覧です。リクエスト / レスポンスの形は Swagger 上で確認できます。

### ガチャ

| メソッド | パス | 説明 |
|---------|-----|------|
| POST | `/api/gacha/draw` | 10 連ガチャ。Body に `gachaId` を渡す |

### ユーザー

| メソッド | パス | 説明 |
|---------|-----|------|
| POST | `/api/user/create` | ユーザー新規作成。Body `{"name": "..."}` |
| POST | `/api/user/login` | ログイン。Body `{"name": "..."}` で userId を返す |

Service 層・Controller の書き方の見本として置いてあります。詳しくは [ヒント: 参考コード](./ヒント-参考コード.md) を参照してください。

### デバッグ用 (`/api/debug/*`)

| メソッド | パス | 説明 |
|---------|-----|------|
| GET | `/api/debug/inventory?userId=` | 所持品一覧（アイテム名・レアリティ・個数） |
| POST | `/api/debug/gacha-draw-one?gachaId=` | `GachaService.DrawOneAsync` を 1 回だけ呼ぶ |
| POST | `/api/debug/item-give?userId=&itemId=&grantCount=` | `UserItemService.GrantAsync` を単体で呼ぶ |
| POST | `/api/debug/item-consume?userId=&itemId=&consumeCount=` | `UserItemService.ConsumeAsync` を単体で呼ぶ |
| GET | `/api/debug/item-has-enough?userId=&itemId=&requiredCount=` | `UserItemService.HasEnoughAsync` を単体で呼ぶ |

Service のメソッドを 1 つずつ単体で呼んだり、DB の中身を API 経由で確認したりするための教材用エンドポイントです。各課題の「動作確認」節で、その課題に使うものを案内しています。
