# マスタいじりワーク【任意】: アイテム追加 / 新バナー追加

**目的**: [メイン課題2 (マスタいじりワーク)](../2-master-workshop.md) の排出確率いじりを体験した人向けの、**もう一歩踏み込んだ任意ワーク**です。マスタを触るだけで新アイテムや新ガチャバナーを増やせることを体感します。

**目安時間**: ワーク2 で 5〜10分、ワーク3 で 10分弱。片方だけつまみ食いも、両方やってもOK。

**位置付け**: **任意**。時間があれば取り組んでください。追加課題A に進んでも問題ありません。

---

## 前提

- [メイン課題2 (マスタいじりワーク)](../2-master-workshop.md) 完了済み (phpMyAdmin での編集操作に慣れている状態)

---

## ワーク2: 新しいアイテムを追加してみる

**やること**: `item_master` に新しいキャラクターを追加して、通常ガチャで排出されるようにします。

### 手順

1. `intern_master.item_master` テーブルを開く → 「挿入」タブ
2. 以下の値を入力して「実行」:
    - `item_id`: **`2009`**
    - `item_type`: **`character`**
    - `name`: **`ドラゴンの卵`** (好きな名前でOKです)
    - `rarity`: **`SSR`**
3. `intern_master.gacha_detail_master` に組み込み → 「挿入」タブ
    - `gacha_id`: **`1`**
    - `item_id`: **`2009`**
    - `weight`: **`5`** (ちょっと出やすめ)
4. 「実行」
5. Swagger で `POST /api/gacha/draw` に `{ "gachaId": 1 }` を投げます

### 期待する変化

- 10連の結果に **`itemId: 2009` (ドラゴンの卵)** が混じって出ます

### 学びどころ

- **コードは一切変えていない**、DB に行を足しただけで新しいアイテムが排出プールに入ります
- **既存の実装 (DrawOneAsync) は変更不要** — 「マスタから取ってくる」構造にしておいたおかげで、拡張が無限に効きます
- これがマスタ駆動設計の醍醐味です

### 発展: 逆に「引かせないようにする」

`gacha_detail_master` から `item_id=2001` の行を **削除** して draw を叩くと、炎の勇者は出なくなります。「特定のガチャからだけ削除」ができるので、期間限定復刻とかも簡単です。

## ワーク3: 新しいガチャバナーを追加してみる

**やること**: `gacha_master` に新しいバナーを追加して、独自の排出プールで抽選します。

### 手順

1. `intern_master.gacha_master` テーブルを開く → 「挿入」タブ
2. 以下の値を入力:
    - `gacha_id`: **`3`**
    - `name`: **`SSR確定ガチャ`**
    - `start_at`: **`2026-01-01 00:00:00`**
    - `end_at`: **`2099-12-31 23:59:59`**
    - `cost_item_id`: **`1001`**
    - `cost_amount`: **`1000`** (10連で 10000 魔石消費、リッチ)
3. 「実行」
4. `gacha_detail_master` に排出プールを追加 (「挿入」タブから複数行いけます):
    - `gacha_id=3, item_id=2001, weight=1`
    - `gacha_id=3, item_id=2002, weight=1`
    - (SSR 2種だけ) → SSR確定になります
5. Swagger で `POST /api/gacha/draw` に `{ "gachaId": 3 }` を投げます

### 期待する変化

- 10連の結果が **全部 SSR** (item_id=2001 と 2002 だけ) になります

### 学びどころ

- ガチャ本体のロジック (`DrawOneAsync`) はどのガチャでも同じコード
- 「どのガチャを引くか」は `gachaId` パラメータで切り替わります
- プランナーが「復刻ガチャを1本追加したい」と言ってきたら、DB に行を追加するだけで対応できます

### 発展: 期間限定を試してみる

`gacha_master.start_at` を **未来の日付** にすると、そのガチャは「まだ開催されていない」状態になります。ただし、現状の実装は期間チェックをしていないので、未来の日付でも引けてしまいます。

**気になる人へ**: これを検知して「未開催エラーを返す」機能を追加するのが、さらなる発展課題です。`GachaDrawController` に日付チェックロジックを足すと実装できます。
